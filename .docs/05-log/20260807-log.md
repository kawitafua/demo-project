## สร้างเอกสาร requirement: ระบบสั่งกาแฟจากที่โต๊ะด้วย QR Code

- สร้าง [[../01-requirements/01-spec/20260807-01-table-qr-ordering|20260807-01-table-qr-ordering]]
- อัปเดต backlog: เพิ่มรายการ "ระบบสั่งกาแฟจากที่โต๊ะด้วย QR Code (สั่ง+จ่าย+สะสมแต้ม)" สถานะ ร่าง
- ประเด็นที่ถาม user:
  - ขอบเขตของระบบ → เลือก ครบวงจร (สั่ง + จ่าย + สมาชิก/แต้มสะสม)
  - วิธีเข้าถึงที่โต๊ะ → เลือก สแกน QR Code ต่อโต๊ะ เปิดเป็นเว็บ
  - การแจ้งออเดอร์ไปบาริสต้า/ครัว → เลือก จอแสดงผลในร้าน (KDS)

## สร้างเอกสาร requirement: หน้า Dashboard ดูยอดขาย

- สร้าง [[../01-requirements/01-spec/20260807-02-dashboard-sales|20260807-02-dashboard-sales]] โดยอ้างอิงกลับไปยัง [[../01-requirements/01-spec/20260807-01-table-qr-ordering|20260807-01-table-qr-ordering]] เนื่องจากใช้ข้อมูลออเดอร์/การชำระเงินจากระบบนั้นเป็นแหล่งข้อมูลยอดขาย (เลือกแนวทางสร้างเอกสารใหม่แยกต่างหาก พร้อม wikilink อ้างอิง)
- อัปเดต backlog: เพิ่มรายการ "หน้า Dashboard ดูยอดขาย (สรุปตามช่วงเวลา + แยกตามสินค้า + export)" สถานะ ร่าง ไว้บนสุดของตาราง
- ประเด็นที่ถาม user:
  - ผู้ใช้งานหน้า dashboard → เลือก เจ้าของร้าน + พนักงาน/บาริสต้าที่ได้รับสิทธิ์ดูรายงาน (ต้องมีระบบสิทธิ์)
  - มิติข้อมูลที่ต้องแสดง → เลือก สรุปยอดขายตามช่วงเวลา + แยกตามสินค้า/เมนู (ไม่แยกตามโต๊ะ/ช่องทาง)
  - Filter → เลือก เลือกช่วงวันที่ได้เอง (custom date range)
  - Export → เลือก ต้องมี export เป็น CSV/Excel
  - แหล่งข้อมูล → เลือก เชื่อมกับข้อมูลออเดอร์/การชำระเงินของระบบสั่งกาแฟ QR (20260807-01-table-qr-ordering)

## สร้างเอกสาร requirement: การเก็บ Audit Log และ PDPA Compliance

- สร้าง [[../01-requirements/01-spec/20260807-03-audit-log-pdpa-compliance|20260807-03-audit-log-pdpa-compliance]] โดยอ้างอิงกลับไปยัง [[../01-requirements/01-spec/20260807-01-table-qr-ordering|20260807-01-table-qr-ordering]] และ [[../01-requirements/01-spec/20260807-02-dashboard-sales|20260807-02-dashboard-sales]] (เลือกแนวทางสร้างเอกสารใหม่แยกต่างหาก พร้อม wikilink อ้างอิง เนื่องจากเป็น cross-cutting concern คนละ scope จากทั้งสองสเปกเดิม)
- อัปเดต backlog: เพิ่มรายการ "Audit Log และ PDPA Compliance (log เหตุการณ์สำคัญ + consent แบบง่าย)" สถานะ ร่าง ไว้บนสุดของตาราง
- ขอบเขตที่ user ยืนยันไว้ล่วงหน้าแล้ว (ไม่ได้ถามซ้ำในรอบนี้):
  - Audit log → ทำเต็มตามที่แนะนำ (เก็บ log 6 ประเภทเหตุการณ์, โครงสร้าง log record, ห้าม log ข้อมูลอ่อนไหวแบบเต็ม, ต้องมี retention period, ต้องมี log integrity)
  - PDPA → ทำเท่าที่จำเป็น (เฉพาะ consent แบบง่าย + privacy notice ตอนลงทะเบียนสมาชิก) และตัด data subject rights, breach-notification workflow, data minimization/anonymization automation ออกจาก scope รอบนี้อย่างชัดเจนตามการตัดสินใจของ user
- ประเด็นที่ยังไม่ชัดเจนตอนสร้างเอกสารครั้งแรก ได้กลับมาถาม user ผ่าน AskUserQuestion แล้วในวันเดียวกัน และอัปเดตเอกสารสเปกให้เป็น Business Rules แทนแล้ว:
  - Retention period ของ audit log → เลือก **90 วัน**
  - สิทธิ์ในการดู audit log → เลือก **เจ้าของร้าน + พนักงานที่ได้รับสิทธิ์ระดับผู้ดูแลระบบ** (แยกจากสิทธิ์ dashboard ยอดขาย)
  - รูปแบบ/สถานที่จัดเก็บ audit log → เลือก **ระบบ log แยกต่างหากจากฐานข้อมูลหลัก**
  - ประเด็นที่ยังเหลือค้าง: รายละเอียดทางเทคนิคของระบบ log แยก (self-hosted/cloud) รอวิเคราะห์ในเอกสารออกแบบ
