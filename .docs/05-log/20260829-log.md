- คำขอ user: "ทำ prototype หน้า login ต่อ" — ตรวจสอบสเปคทั้ง 3 ฉบับแล้วพบว่า **ไม่มี requirement spec ฉบับใดระบุรายละเอียดหน้า login โดยตรง** มีเพียง [[../02-design/01-prototypes/20260829-01-user-journeys|Journey 3]] ที่กล่าวถึง "Login เข้าสู่ระบบ" เป็นขั้นตอนหนึ่งก่อนตรวจสอบสิทธิ์ role เท่านั้น และ `DASH-05` เองก็มีประเด็นเปิดเรื่องรายละเอียดสิทธิ์/บทบาทผู้ใช้ที่ยังไม่ระบุ จึงหยุดถาม user ก่อนลงมือ (ไม่ตัดสินใจแทน) โดยเสนอ 3 แนวทางพร้อมข้อดี-ข้อเสีย: (A) login ขั้นต่ำสุด username/password + ลืมรหัสผ่าน placeholder ระบุเป็นสมมติฐานชั่วคราว, (B) หยุดรอให้สร้าง requirement spec หน้า login ก่อนผ่าน `/create-requirement`, (C) ทำ minimal ที่สุดตาม journey ที่ยืนยันแล้วเท่านั้น (ไม่มี field กรอกจริงจัง) — user เลือกแนวทาง A
- เอกสารอ้างอิงที่ใช้: [[../01-requirements/01-spec/20260807-02-dashboard-sales|20260807-02-dashboard-sales]], [[../01-requirements/01-spec/20260807-03-audit-log-pdpa-compliance|20260807-03-audit-log-pdpa-compliance]], [[../01-requirements/02-plan/20260829-01-feature-list|20260829-01-feature-list]] (เฉพาะ `AUDIT-01`, `DASH-05`), [[../02-design/01-prototypes/20260829-01-user-journeys|20260829-01-user-journeys]] (เฉพาะ Journey 3 ขั้นตอนที่ 1-2)
- Design System: ใช้ [[../02-design/01-prototypes/20260829-02-design-system|20260829-02-design-system]] ที่มีอยู่แล้วเป็นหลัก — หน้า login ไม่ใช่ touchpoint ที่ระบุไว้ตอนสร้าง design system จึงยึด token ทั่วไป (2.1 Colors, 2.2 Typography) และ component ร่วม (3.1 Button, Alert) แทน component เฉพาะ พร้อมบันทึกไว้ในไฟล์หน้าจอว่าควรเพิ่ม component "Text Input" อย่างเป็นทางการในอนาคต
- Version: ตรวจสอบด้วย Glob พบ `prototype-v1` มีอยู่แล้ว (dashboard + หน้าสั่งเมนูลูกค้า + จอ KDS) จึงถาม user ตามกฎของ skill ว่าจะสร้าง `prototype-v2` ใหม่หรือเพิ่มไฟล์ในเวอร์ชันเดิม พร้อมวิเคราะห์ว่าเป็นหน้าจอใหม่ที่ไม่ทับซ้อนกับ 3 หน้าจอเดิม จึงแนะนำเพิ่มไฟล์ในเวอร์ชันเดิม (Recommended) — user ยืนยันเลือกตัวเลือกนี้ (ไม่สร้าง prototype-v2)
- เสนอแผนเต็ม (เอกสารอ้างอิง, design system, version, รายชื่อ 2 state + ส่วน handoff ของหน้าจอ) ให้ user ยืนยันก่อนสร้างไฟล์จริงตามขั้นตอนบังคับของ skill — user ยืนยัน "ดำเนินการตามแผนนี้" แล้วจึงลงมือ
