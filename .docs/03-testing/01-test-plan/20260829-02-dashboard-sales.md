> สร้างเมื่อ 2026-08-29
> อ้างอิง: [[../../01-requirements/01-spec/20260807-02-dashboard-sales|20260807-02-dashboard-sales]]

## ขอบเขตการทดสอบ (Scope)

- ทดสอบ:
  - การเข้าถึงหน้า dashboard เฉพาะบทบาทเจ้าของร้าน (full access)/พนักงานที่ได้รับสิทธิ์ดูรายงาน (read-only) และการปฏิเสธผู้ใช้บทบาทอื่น (`DASH-05`) — ทดสอบเฉพาะผลลัพธ์ pass/fail ของการเข้าถึงด้วย 2 บทบาทตัวอย่างที่ยืนยันแล้วเท่านั้น ไม่รวมกลไก/UI การกำหนด-มอบสิทธิ์พนักงาน (ดู "ไม่ทดสอบ")
  - สรุปยอดขายตามช่วงเวลา (รายวัน/รายสัปดาห์/รายเดือน) นับเฉพาะออเดอร์ที่ชำระเงินสำเร็จ (`DASH-01`)
  - รายงานยอดขายแยกตามสินค้า/เมนู พร้อมจัดอันดับเมนูขายดี (`DASH-02`)
  - ตัวกรองเลือกช่วงวันที่เอง (custom date range) การอัปเดตข้อมูลทั้งหน้าตามช่วงที่เลือก และการห้ามเลือกวันที่ในอนาคต (ยืนยันแล้วเมื่อ 2026-08-29) (`DASH-03`)
  - กราฟแท่งประกอบยอดขายตามช่วงเวลา, pie chart สัดส่วนยอดขายแยกตามเมนู, และ line chart เปรียบเทียบแนวโน้มช่วงเวลาปัจจุบันกับช่วงก่อนหน้า (ทั้ง 3 ชนิดกราฟยืนยัน scope แล้วเมื่อ 2026-08-29) และความสอดคล้องกับตัวเลขสรุป/ตาราง (`DASH-06`)
  - ปุ่ม export ข้อมูลยอดขายเป็น CSV/Excel พร้อม confirm modal, ความตรงกันของข้อมูลกับตัวกรองที่เลือกอยู่ในระดับภาพรวม, และความครบถ้วนของคอลัมน์ทั้งคอลัมน์พื้นฐานและคอลัมน์ระดับออเดอร์ (order ID, เวลาที่ชำระเงิน, ช่องทางชำระเงิน — ยืนยันแล้วเมื่อ 2026-08-29) (`DASH-04`)
- ไม่ทดสอบ (out of scope รอบนี้):
  - UI/ฟีเจอร์จัดการสิทธิ์ผู้ใช้ (หน้าจอที่เจ้าของร้านใช้มอบ/เพิกถอนสิทธิ์ดูรายงานให้พนักงาน) — ยืนยันแล้วว่ามี 2 ระดับสิทธิ์เป็น business rule แต่ยังไม่ออกแบบ/ทดสอบ UI การจัดการในรอบนี้
  - Export เป็น PDF, การแยกยอดขายตามโต๊ะ/ช่องทางการสั่ง, รายงานเชิงวิเคราะห์เชิงลึก (พยากรณ์ยอดขาย ฯลฯ) — out of scope ตามสเปคต้นทางอยู่แล้ว
  - การบันทึก audit log เหตุการณ์ `data.exported` เมื่อ export สำเร็จ — เป็น scope ของ [[../../01-requirements/01-spec/20260807-03-audit-log-pdpa-compliance|20260807-03-audit-log-pdpa-compliance]] แยกต่างหาก
  - รูปแบบ empty state ที่แน่นอนเมื่อเลือกช่วงวันที่ที่ไม่มีข้อมูล — ยังไม่มี business rule ระบุรายละเอียด UI จึงทดสอบเพียงว่าไม่ error/ค้าง (ดู TC-10) ไม่ตัดสิน pass/fail ในรายละเอียด UI เฉพาะเจาะจง

> หมายเหตุ: 4 ประเด็นที่เคยระบุไว้เป็นคำถามค้าง (คอลัมน์ไฟล์ export, กลไก RBAC/ระดับสิทธิ์, ชนิดกราฟเพิ่มเติม, ข้อจำกัดช่วงวันที่) ได้รับคำตอบจาก user แล้วเมื่อ 2026-08-29 จึงอัปเดต scope ด้านบนและเพิ่ม test case ใหม่ (TC-15 ถึง TC-19) ให้ครอบคลุมครบแล้ว

## Test Environment / Test Data

- บัญชีทดสอบ: เจ้าของร้าน 1 บัญชี, พนักงานที่ได้รับสิทธิ์ดูรายงาน 1 บัญชี, พนักงาน/ผู้ใช้ที่ไม่มีสิทธิ์ดูรายงาน 1 บัญชี (เช่น บาริสต้าทั่วไป) สำหรับทดสอบ Authorized/Access Denied View
- ข้อมูลออเดอร์ทดสอบ: มีออเดอร์ที่ชำระเงินสำเร็จและไม่สำเร็จปะปนกัน ครอบคลุมช่วงเวลาอย่างน้อย 1 เดือนย้อนหลัง เพื่อให้ทดสอบมุมมองรายวัน/รายสัปดาห์/รายเดือนได้ครบ
- เมนูทดสอบอย่างน้อย 5 รายการที่มียอดขายรวมต่างกันชัดเจน เพื่อยืนยันการจัดอันดับเมนูขายดี (อันดับ 1-3)
- ช่วงวันที่ทดสอบ: อย่างน้อย 2 ช่วง — ช่วงที่มีข้อมูลยอดขาย และช่วงที่ไม่มีข้อมูลยอดขายเลย (เพื่อสังเกตพฤติกรรมเมื่อไม่มีข้อมูล ไม่ผูกเป็นเงื่อนไข pass/fail ที่ชัดเจนเนื่องจากยังไม่มี business rule ระบุ empty state)
- ออเดอร์ทดสอบสำหรับตรวจสอบคอลัมน์ export ระดับออเดอร์: อย่างน้อย 2-3 ออเดอร์ที่ทราบ order ID, เวลาที่ชำระเงินสำเร็จ, และช่องทางชำระเงิน (ครอบคลุมมากกว่า 1 ช่องทาง) แน่นอนล่วงหน้า
- ข้อมูลสำหรับทดสอบ line chart เปรียบเทียบช่วงเวลา: มีออเดอร์ชำระเงินสำเร็จที่ทราบยอดขายแน่นอนทั้งในช่วงเวลาปัจจุบัน (เช่น 7 วันล่าสุด) และช่วงก่อนหน้าที่มีความยาวเท่ากัน (เช่น 7 วันก่อนหน้านั้น)
- ข้อมูล/อุปกรณ์สำหรับทดสอบข้อจำกัดช่วงวันที่: date range picker ที่เปิดให้ทดสอบเลือกวันที่ในอนาคต (เช่น พรุ่งนี้/เดือนถัดไป) เพื่อยืนยันว่าถูกปฏิเสธ/ปิดกั้น
- อุปกรณ์: desktop browser ตามที่ wireframe ออกแบบไว้ ([[../../02-design/01-prototypes/prototype-v1/sales-dashboard|prototype-v1/sales-dashboard]])

| TC-14 | ข้อมูลในไฟล์ export ตรงกับตัวกรองที่เลือกอยู่ (ระดับภาพรวม) | เลือกช่วงวันที่ที่ทราบยอดขายรวม/รายการเมนูแน่นอนแล้ว | 1. เลือกช่วงวันที่ที่ต้องการ 2. กด export และยืนยัน 3. เปิดไฟล์ที่ได้ตรวจสอบยอดรวม/รายการเมนู | ยอดรวมและรายการเมนูในไฟล์ที่ export ตรงกับข้อมูลที่แสดงบนหน้าจอ ณ ช่วงวันที่ที่เลือกอยู่ขณะนั้น (ตรวจสอบเฉพาะยอดรวม/รายการเมนูระดับภาพรวม ส่วนคอลัมน์ระดับออเดอร์ตรวจสอบละเอียดใน TC-19) | AC5 |
| TC-15 | พนักงานที่ได้รับสิทธิ์ (read-only) ใช้งานฟีเจอร์ export ได้เหมือนเจ้าของร้าน | ล็อกอินด้วยบัญชีพนักงานที่ได้รับสิทธิ์ดูรายงาน อยู่ในหน้า dashboard | 1. เลือกช่วงวันที่ 2. กดปุ่ม "Export CSV/Excel" 3. กด "ยืนยัน Export" | พนักงานที่ได้รับสิทธิ์ (read-only) สามารถกด export ข้อมูลได้สำเร็จเช่นเดียวกับเจ้าของร้าน (บทบาท "read-only" หมายถึงดูข้อมูลอย่างเดียว ไม่ใช่การจำกัดสิทธิ์ export ซึ่งเป็นฟีเจอร์การดู/ดาวน์โหลดข้อมูล ไม่ใช่การแก้ไขข้อมูล) | AC6 |
| TC-16 | pie chart สัดส่วนยอดขายแยกตามเมนูถูกต้องตรงกับตาราง | มีเมนูทดสอบยอดขายต่างกันชัดเจนในช่วงวันที่ที่เลือก (ใช้ข้อมูลเดียวกับ TC-08) | 1. เข้าหน้า dashboard เลือกช่วงวันที่ที่มีข้อมูล 2. ดู pie chart สัดส่วนยอดขายแยกตามเมนู 3. เปรียบเทียบสัดส่วน/ยอดขายแต่ละเมนูในกราฟกับตัวเลขในตารางยอดขายแยกตามเมนู | สัดส่วนที่แสดงใน pie chart ตรงกับสัดส่วนที่คำนวณได้จากยอดขายจริงในตาราง (ผลรวมสัดส่วนทุกเมนูเท่ากับ 100%) | AC8 |
| TC-17 | line chart เปรียบเทียบแนวโน้มยอดขายช่วงปัจจุบันกับช่วงก่อนหน้าถูกต้อง | มีออเดอร์ชำระเงินสำเร็จที่ทราบยอดขายแน่นอนทั้งช่วง 7 วันล่าสุดและ 7 วันก่อนหน้านั้น | 1. เลือกช่วงวันที่ปัจจุบัน (7 วันล่าสุด) 2. ดู line chart เปรียบเทียบแนวโน้ม 3. ตรวจสอบค่าของเส้นช่วงปัจจุบันและเส้นช่วงก่อนหน้ากับยอดขายจริงของแต่ละช่วง | line chart แสดง 2 เส้นแยกกันชัดเจน (ช่วงปัจจุบัน / ช่วงก่อนหน้าที่มีความยาวเท่ากัน) และค่าที่แสดงในแต่ละเส้นตรงกับยอดขายจริงของช่วงเวลานั้นๆ | AC9 |
| TC-18 | ไม่สามารถเลือกวันที่ในอนาคตในตัวกรองช่วงวันที่ได้ | อยู่ในหน้า dashboard เปิดตัวกรองช่วงวันที่ (date range picker) | 1. เปิด date range picker 2. พยายามเลือกวันที่ที่เป็นอนาคต (เช่น พรุ่งนี้ หรือเดือนถัดไป) เป็นวันสิ้นสุดช่วง 3. สังเกตพฤติกรรมของตัวกรองและลองยืนยันตัวกรอง | ระบบไม่อนุญาตให้เลือกวันที่ในอนาคตเป็นส่วนหนึ่งของช่วง (เช่น วันที่ในอนาคตถูก disable ใน date picker หรือระบบปฏิเสธ/แจ้งเตือนเมื่อพยายามยืนยัน) ช่วงวันที่ที่ใช้งานจริงต้องไม่มีวันที่เกินวันปัจจุบันเสมอ | AC10 |
| TC-19 | ไฟล์ export มีคอลัมน์ระดับออเดอร์ครบถ้วนตามที่ยืนยันแล้ว | มีออเดอร์ทดสอบที่ทราบ order ID, เวลาที่ชำระเงินสำเร็จ, และช่องทางชำระเงินแน่นอน อยู่ในช่วงวันที่ที่จะ export | 1. เลือกช่วงวันที่ที่มีออเดอร์ทดสอบ 2. กด export และยืนยัน 3. เปิดไฟล์ตรวจสอบคอลัมน์และค่าในแต่ละแถว | ไฟล์ export มีคอลัมน์ครบทั้งคอลัมน์พื้นฐาน (วันที่, ชื่อเมนู, จำนวนที่ขาย, ยอดขายรวม) และคอลัมน์ระดับออเดอร์ (order ID, เวลาที่ชำระเงิน, ช่องทางชำระเงิน) โดยค่าทุกแถวตรงกับข้อมูลออเดอร์จริง | AC5 |
