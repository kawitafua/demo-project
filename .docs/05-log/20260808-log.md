# Log 2026-08-08

## สร้างเอกสาร technical design: Audit Log และ PDPA Consent

- สร้าง [[../02-design/02-technical/20260808-01-audit-log-pdpa-technical-design|20260808-01-audit-log-pdpa-technical-design]] ต่อยอดจาก [[../01-requirements/01-spec/20260807-03-audit-log-pdpa-compliance|20260807-03-audit-log-pdpa-compliance]]
- ประเด็นที่ถาม user:
  - โปรเจกต์ยังไม่มี tech stack ที่เลือกไว้ → เลือก ออกแบบแบบ tech-agnostic (ระบุ data model/architecture/security control โดยไม่ผูกกับเทคโนโลยีเฉพาะ, ปล่อยการเลือกเทคโนโลยีจริงเป็นประเด็นค้างจนกว่าจะเลือก stack โดยรวม)
- เนื้อหาเอกสาร: architecture แบบ Audit Log Service แยกจาก DB หลัก, data model ของ log entry และ consent field บนข้อมูลสมาชิก, action-to-target mapping ตาม business rules เดิม, access control (owner + system_admin เท่านั้น, แยกจากสิทธิ์ dashboard ยอดขาย), retention job (hard delete ทุก 90 วัน), และ logical interface (AppendLogEntry/QueryLogEntries/PurgeExpiredEntries)
- ประเด็นที่ยังเหลือค้าง: เทคโนโลยีจริงของ log store, กลไก async delivery, UI สำหรับ query log (ไม่อยู่ใน scope นี้)
