# หน้า Dashboard ดูยอดขาย

> สร้างเมื่อ 2026-08-07
> อ้างอิง: [[../01-spec/20260807-01-table-qr-ordering|20260807-01-table-qr-ordering]] (แหล่งข้อมูลออเดอร์/การชำระเงิน)

## ความต้องการ (Requirement)

เจ้าของร้านและพนักงานที่ได้รับสิทธิ์ต้องการหน้า dashboard สำหรับดูยอดขายของร้าน เพื่อติดตามภาพรวมธุรกิจและสินค้าขายดี โดยดึงข้อมูลจากออเดอร์/การชำระเงินของระบบสั่งกาแฟผ่าน QR Code ที่มีอยู่แล้ว

รายละเอียดตามคำตอบที่ยืนยันกับผู้ใช้:

- **ผู้ใช้งาน**: เจ้าของร้าน และพนักงาน/บาริสต้าที่ได้รับสิทธิ์ดูรายงานเท่านั้น (ไม่ใช่ admin เพียงคนเดียว และไม่ใช่ทุกคนที่ login เข้าระบบได้ — ต้องมีการกำหนดสิทธิ์/บทบาทผู้ใช้ในการเข้าถึงหน้านี้) — **ยืนยันเพิ่มเติม 2026-08-29**: มี 2 ระดับสิทธิ์เท่านั้น คือ "เจ้าของร้าน" (full access) และ "พนักงานที่ได้รับสิทธิ์ดูรายงาน" (read-only ดูได้อย่างเดียว) เจ้าของร้านเป็นผู้กำหนดสิทธิ์พนักงานเอง แต่ **UI/ฟีเจอร์สำหรับจัดการสิทธิ์ (มอบสิทธิ์ให้พนักงานคนไหน) ยังไม่อยู่ใน scope การออกแบบ/ทดสอบรอบนี้** เป็นเพียงการยืนยัน business rule ระดับสิทธิ์เท่านั้น
- **มิติข้อมูลที่ต้องแสดง**:
  - สรุปยอดขายตามช่วงเวลา (รายวัน/รายสัปดาห์/รายเดือน)
  - ยอดขายแยกตามสินค้า/เมนู (เมนูขายดี, ยอดขายต่อเมนู)
  - ไม่ต้องแยกตามโต๊ะหรือช่องทางการสั่งในรอบนี้
- **Filter**: เลือกช่วงวันที่ได้เอง (custom date range) — **ยืนยันเพิ่มเติม 2026-08-29**: ไม่จำกัดความยาวของช่วงวันที่ แต่**ห้ามเลือกวันที่ในอนาคต** (เพราะไม่มีข้อมูลยอดขายในอนาคต)
- **Export**: ต้องมีปุ่ม export ข้อมูลเป็นไฟล์ CSV/Excel — **ยืนยันเพิ่มเติม 2026-08-29**: นอกจากคอลัมน์พื้นฐาน (วันที่, ชื่อเมนู, จำนวนที่ขาย, ยอดขายรวม) ต้องมีคอลัมน์ระดับออเดอร์เพิ่มเติมด้วย ได้แก่ order ID, เวลาที่ชำระเงิน, และช่องทางชำระเงิน เพื่อให้นำไป reconcile กับบัญชีได้
- **กราฟ/ชาร์ต** (เพิ่มเติม 2026-08-29): ยืนยันกับ user แล้วว่าต้องมีกราฟแท่งประกอบยอดขายตามช่วงเวลาในหน้า dashboard ด้วย (ไม่ใช่แค่ตัวเลข/ตาราง) เพื่อให้เห็นแนวโน้มได้ง่ายขึ้น — **ยืนยันเพิ่มเติมอีกครั้ง 2026-08-29**: นอกจากกราฟแท่งแล้ว ต้องมีทั้ง **pie chart** (สัดส่วนยอดขายแยกตามเมนู) และ **line chart** (เปรียบเทียบแนวโน้มยอดขายของช่วงเวลาปัจจุบันกับช่วงเวลาก่อนหน้าที่มีความยาวเท่ากัน) เพิ่มเติมด้วย
- **แหล่งข้อมูล**: เชื่อมกับข้อมูลออเดอร์/การชำระเงินของระบบสั่งกาแฟผ่าน QR Code ตาม [[../01-spec/20260807-01-table-qr-ordering|20260807-01-table-qr-ordering]] — นับยอดขายจากออเดอร์ที่ชำระเงินสำเร็จเท่านั้น (สอดคล้องกับ business rule ของเอกสารนั้น)

## Scope

- ทำ:
  - หน้า dashboard สรุปยอดขายตามช่วงเวลา (รายวัน/รายสัปดาห์/รายเดือน)
  - รายงานยอดขายแยกตามสินค้า/เมนู พร้อมจัดอันดับเมนูขายดี
  - ตัวกรองเลือกช่วงวันที่ได้เอง (custom date range) ไม่จำกัดความยาวช่วง แต่ห้ามเลือกวันที่ในอนาคต (ยืนยันเพิ่มเติม 2026-08-29)
  - ปุ่ม export ข้อมูลยอดขายเป็น CSV/Excel รวมคอลัมน์ระดับออเดอร์ (order ID, เวลาที่ชำระเงิน, ช่องทางชำระเงิน) นอกเหนือจากคอลัมน์พื้นฐาน (ยืนยันเพิ่มเติม 2026-08-29)
  - การกำหนดสิทธิ์เข้าถึงหน้านี้เฉพาะเจ้าของร้าน (full access) และพนักงานที่ได้รับสิทธิ์ (read-only) — 2 ระดับสิทธิ์ตามที่ยืนยันแล้ว (ไม่รวม UI จัดการสิทธิ์ ดูหัวข้อ "ไม่ทำ")
  - กราฟแท่งประกอบยอดขายตามช่วงเวลา (ยืนยัน scope เพิ่มเติมเมื่อ 2026-08-29)
  - pie chart สัดส่วนยอดขายแยกตามเมนู (ยืนยัน scope เพิ่มเติมเมื่อ 2026-08-29)
  - line chart เปรียบเทียบแนวโน้มยอดขายของช่วงเวลาปัจจุบันกับช่วงเวลาก่อนหน้าที่มีความยาวเท่ากัน (ยืนยัน scope เพิ่มเติมเมื่อ 2026-08-29)
- ไม่ทำ (ยังไม่อยู่ใน scope รอบนี้):
  - การแยกยอดขายตามโต๊ะ หรือตามช่องทางการสั่ง
  - Export เป็น PDF
  - รายงานเชิงวิเคราะห์เชิงลึกอื่น ๆ เช่น พยากรณ์ยอดขาย, เปรียบเทียบกับคู่แข่ง
  - UI/ฟีเจอร์จัดการสิทธิ์ผู้ใช้ (หน้าจอที่เจ้าของร้านใช้มอบ/เพิกถอนสิทธิ์ดูรายงานให้พนักงาน) — ยืนยันแล้วว่ามี 2 ระดับสิทธิ์เป็น business rule แต่ยังไม่ออกแบบ/ทดสอบ UI การจัดการในรอบนี้ (ยืนยันเพิ่มเติม 2026-08-29)

## User Stories / Use Cases

- ในฐานะเจ้าของร้าน ฉันต้องการดูสรุปยอดขายรายวัน/รายสัปดาห์/รายเดือน เพื่อติดตามภาพรวมธุรกิจ
- ในฐานะเจ้าของร้าน ฉันต้องการดูเมนูขายดีและยอดขายต่อเมนู เพื่อวางแผนสต๊อกและโปรโมชัน
- ในฐานะเจ้าของร้าน ฉันต้องการเลือกช่วงวันที่เองเพื่อดูยอดขายในช่วงที่สนใจ (เช่น ช่วงจัดโปรโมชัน)
- ในฐานะเจ้าของร้าน ฉันต้องการ export ข้อมูลยอดขายเป็น CSV/Excel เพื่อนำไปวิเคราะห์ต่อหรือส่งให้นักบัญชี
- ในฐานะพนักงานที่ได้รับสิทธิ์ ฉันต้องการเข้าดู dashboard ยอดขายได้ โดยไม่ต้องพึ่งเจ้าของร้านทุกครั้ง

## Business Rules / เงื่อนไข

- การเข้าถึงหน้า dashboard ต้องจำกัดเฉพาะผู้ใช้ที่มีบทบาท **"เจ้าของร้าน" (full access)** หรือ **"พนักงานที่ได้รับสิทธิ์ดูรายงาน" (read-only)** เท่านั้น — มี **2 ระดับสิทธิ์** ตามที่ยืนยันแล้ว เจ้าของร้านเป็นผู้กำหนดสิทธิ์พนักงานเอง (ยืนยันกับ user แล้วเมื่อ 2026-08-29) — หมายเหตุ: กลไก/UI การมอบสิทธิ์ให้พนักงานยังไม่อยู่ใน scope การออกแบบ/ทดสอบรอบนี้ เป็นเพียงการยืนยัน business rule ระดับสิทธิ์เท่านั้น
- ยอดขายที่นับในรายงานต้องมาจากออเดอร์ที่ชำระเงินสำเร็จเท่านั้น (สอดคล้องกับเงื่อนไขใน [[../01-spec/20260807-01-table-qr-ordering|20260807-01-table-qr-ordering]])
- ตัวกรองช่วงวันที่ต้องรองรับการเลือกช่วงเองแบบอิสระ (ไม่จำกัดแค่ตัวเลือกสำเร็จรูป) ไม่จำกัดความยาวของช่วงวันที่ แต่**ห้ามเลือกวันที่ในอนาคต** เนื่องจากไม่มีข้อมูลยอดขายในอนาคต (ยืนยันกับ user แล้วเมื่อ 2026-08-29)
- ไฟล์ export ต้องมีข้อมูลตรงกับที่แสดงบนหน้าจอตามตัวกรองที่เลือกอยู่ ณ ขณะนั้น และต้องมีคอลัมน์อย่างน้อย: วันที่, ชื่อเมนู, จำนวนที่ขาย, ยอดขายรวม (คอลัมน์พื้นฐาน) รวมถึง **order ID, เวลาที่ชำระเงิน, และช่องทางชำระเงิน** (คอลัมน์ระดับออเดอร์ เพื่อ reconcile กับบัญชี — ยืนยันกับ user แล้วเมื่อ 2026-08-29)
- นอกจากกราฟแท่งประกอบยอดขายตามช่วงเวลาแล้ว หน้า dashboard ต้องมี **pie chart** แสดงสัดส่วนยอดขายแยกตามเมนู และ **line chart** เปรียบเทียบแนวโน้มยอดขายของช่วงเวลาปัจจุบันกับช่วงเวลาก่อนหน้าที่มีความยาวเท่ากัน (ยืนยันกับ user แล้วเมื่อ 2026-08-29)

## Acceptance Criteria

- [ ] AC1: ระบบแสดงสรุปยอดขายของช่วงเวลาที่เลือก (ยอดขายรวม, จำนวนออเดอร์, ยอดขายเฉลี่ยต่อออเดอร์) โดยสลับมุมมองได้ทั้งรายวัน/รายสัปดาห์/รายเดือน และนับเฉพาะออเดอร์ที่ชำระเงินสำเร็จเท่านั้น
- [ ] AC2: ระบบแสดงตารางยอดขายแยกตามสินค้า/เมนู พร้อมจัดอันดับเมนูขายดี (เน้นอันดับ 1-3 ให้เห็นชัดเจน) โดยข้อมูลอ้างอิงจากออเดอร์ที่ชำระเงินสำเร็จเท่านั้นเช่นเดียวกับ AC1
- [ ] AC3: ผู้ใช้เลือกช่วงวันที่เอง (custom date range) ได้อย่างอิสระ ไม่จำกัดเฉพาะตัวเลือกสำเร็จรูป และเมื่อเปลี่ยนช่วงวันที่ ตัวเลขสรุป/กราฟ/ตารางทั้งหมดในหน้าเดียวกันต้องอัปเดตให้ตรงกับช่วงที่เลือกเสมอ
- [ ] AC4: หน้า dashboard แสดงกราฟแท่งประกอบยอดขายตามช่วงเวลาที่เลือก และตัวเลขในกราฟต้องสอดคล้องกับตัวเลขสรุป/ตารางในหน้าเดียวกัน
- [ ] AC5: มีปุ่ม export ข้อมูลยอดขายเป็นไฟล์ CSV/Excel พร้อมขั้นตอนยืนยันก่อน export จริง และข้อมูลในไฟล์ที่ export ออกมาต้องตรงกับข้อมูล (ตามตัวกรองช่วงวันที่/มุมมองเวลา) ที่แสดงอยู่บนหน้าจอ ณ ขณะนั้นเสมอ โดยไฟล์ต้องมีคอลัมน์พื้นฐาน (วันที่, ชื่อเมนู, จำนวนที่ขาย, ยอดขายรวม) ครบถ้วน **รวมถึงคอลัมน์ระดับออเดอร์เพิ่มเติม (order ID, เวลาที่ชำระเงิน, ช่องทางชำระเงิน)** ตามที่ยืนยันแล้วเมื่อ 2026-08-29
- [ ] AC6: ผู้ใช้ที่มีบทบาท "เจ้าของร้าน" (full access) หรือ "พนักงานที่ได้รับสิทธิ์ดูรายงาน" (read-only) เข้าถึงและใช้งานหน้า dashboard ได้ตามปกติ (Authorized View) — ทดสอบเฉพาะพฤติกรรมการเข้าถึง/ดูข้อมูลตาม 2 ระดับสิทธิ์นี้เท่านั้น ไม่รวม UI การมอบ/จัดการสิทธิ์ (out of scope รอบนี้ ตามที่ยืนยันแล้วเมื่อ 2026-08-29)
- [ ] AC7: ผู้ใช้ที่ไม่มีบทบาทดังกล่าว ต้องถูกปฏิเสธการเข้าถึงหน้า dashboard และเห็นหน้าจอ Access Denied แทน (หมายเหตุ: ทดสอบเฉพาะผลลัพธ์การเข้าถึงแบบ 2 บทบาทตัวอย่างที่ยืนยันแล้วเท่านั้น ส่วนกลไก/UI การกำหนด-มอบสิทธิ์พนักงานยังไม่อยู่ใน scope รอบนี้)
- [ ] AC8: หน้า dashboard แสดง pie chart สัดส่วนยอดขายแยกตามเมนูของช่วงเวลาที่เลือก และสัดส่วนที่แสดงต้องสอดคล้องกับตัวเลขในตารางยอดขายแยกตามเมนู (AC2) (ยืนยันเพิ่มเติม 2026-08-29)
- [ ] AC9: หน้า dashboard แสดง line chart เปรียบเทียบแนวโน้มยอดขายของช่วงเวลาปัจจุบันที่เลือกอยู่ กับช่วงเวลาก่อนหน้าที่มีความยาวเท่ากัน (period-over-period) (ยืนยันเพิ่มเติม 2026-08-29)
- [ ] AC10: ตัวกรองช่วงวันที่ (custom date range) ต้อง**ไม่อนุญาต**ให้ผู้ใช้เลือกวันที่ในอนาคตเป็นส่วนหนึ่งของช่วงที่เลือก (ยืนยันเพิ่มเติม 2026-08-29)

## ประเด็นที่ยังไม่ชัดเจน (รอตัดสินใจในรอบถัดไป)

4 ประเด็นเดิม (การกำหนดสิทธิ์/บทบาทผู้ใช้, คอลัมน์ไฟล์ export, ชนิดกราฟเพิ่มเติม, ข้อจำกัดช่วงวันที่) ได้รับการยืนยันกับ user แล้วเมื่อ 2026-08-29 (ดู Business Rules และ Acceptance Criteria ด้านบน):

- ~~รายละเอียดการกำหนดสิทธิ์/บทบาทผู้ใช้ (ใครเป็นผู้กำหนดสิทธิ์พนักงาน, มีกี่ระดับสิทธิ์)~~ — ยืนยันแล้ว: มี 2 ระดับสิทธิ์ (เจ้าของร้าน full access / พนักงานที่ได้รับสิทธิ์ read-only) เจ้าของร้านเป็นผู้กำหนดเอง แต่ **UI/ฟีเจอร์จัดการสิทธิ์ยังไม่อยู่ใน scope การออกแบบ/ทดสอบรอบนี้** (เป็นเพียงการยืนยัน business rule ระดับสิทธิ์เท่านั้น)
- ~~รูปแบบ/คอลัมน์ที่ต้องมีในไฟล์ export CSV/Excel~~ — ยืนยันแล้ว: เพิ่มคอลัมน์ระดับออเดอร์ (order ID, เวลาที่ชำระเงิน, ช่องทางชำระเงิน) จากคอลัมน์พื้นฐานเดิม (วันที่, ชื่อเมนู, จำนวนที่ขาย, ยอดขายรวม) เพื่อ reconcile กับบัญชี
- ~~ชนิดกราฟเพิ่มเติมนอกจากกราฟแท่ง (เช่น pie chart สัดส่วนเมนู)~~ — ยืนยันแล้ว: ต้องมีทั้ง pie chart (สัดส่วนยอดขายแยกตามเมนู) และ line chart (เปรียบเทียบแนวโน้มช่วงเวลาปัจจุบันกับช่วงก่อนหน้า) เพิ่มจากกราฟแท่งเดิม
- ~~ข้อจำกัด/ขอบเขตของการเลือกช่วงวันที่เอง (custom date range)~~ — ยืนยันแล้ว: ไม่จำกัดความยาวช่วง แต่ห้ามเลือกวันที่ในอนาคต

ปัจจุบันไม่มีประเด็นค้างเพิ่มเติมในสเปคนี้แล้ว
