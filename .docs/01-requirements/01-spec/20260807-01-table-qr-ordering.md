# ระบบสั่งกาแฟจากที่โต๊ะด้วย QR Code

> สร้างเมื่อ 2026-08-07

## ความต้องการ (Requirement)

ลูกค้าที่เข้ามาในร้านกาแฟสามารถสั่งเมนูได้เองจากที่โต๊ะ โดยไม่ต้องเดินไปสั่งที่แคชเชียร์ ระบบครอบคลุมตั้งแต่การสั่ง การชำระเงิน ไปจนถึงระบบสมาชิก/สะสมแต้ม และแจ้งออเดอร์ไปยังบาริสต้าแบบเรียลไทม์

รายละเอียดตามคำตอบที่ยืนยันกับผู้ใช้:

- **ขอบเขต**: ครบวงจร — สั่งเมนู, ชำระเงินออนไลน์ในระบบเลย (ไม่ต้องเดินไปแคชเชียร์), และมีระบบสมาชิก/สะสมแต้ม
- **วิธีเข้าถึงที่โต๊ะ**: ลูกค้าสแกน QR Code ที่ติดไว้ประจำโต๊ะ เปิดเป็นหน้าเว็บสั่งของทันที (ไม่ต้องติดตั้งแอป)
- **การแจ้งออเดอร์**: ออเดอร์ที่สั่งเข้ามาแสดงผลบนจอในร้าน (Kitchen Display System - KDS) ให้บาริสต้าเห็นแบบเรียลไทม์

## Scope

- ทำ:
  - หน้าเว็บสั่งเมนู เข้าถึงผ่านการสแกน QR Code ต่อโต๊ะ (ระบุเลขโต๊ะอัตโนมัติจาก QR)
  - ตะกร้าสั่งซื้อ + ชำระเงินออนไลน์ในระบบ
  - ระบบสมาชิก/สะสมแต้มสำหรับลูกค้า
  - จอแสดงผลออเดอร์ (KDS) สำหรับบาริสต้า/ครัว อัปเดตแบบเรียลไทม์
- ไม่ทำ (ยังไม่อยู่ใน scope รอบนี้):
  - แอปมือถือเฉพาะของร้าน (ใช้เว็บผ่าน QR เท่านั้น)
  - ระบบจัดการหลังบ้านอื่น ๆ ที่ไม่เกี่ยวกับการสั่ง/จ่าย/สะสมแต้ม เช่น บริหารสต๊อกวัตถุดิบ (รอวิเคราะห์แยกในเอกสารอื่น)

## User Stories / Use Cases

- ในฐานะลูกค้า ฉันต้องการสแกน QR Code ที่โต๊ะ เพื่อเปิดเมนูและสั่งกาแฟได้เองโดยไม่ต้องรอพนักงาน
- ในฐานะลูกค้า ฉันต้องการชำระเงินผ่านระบบได้ทันทีหลังสั่ง โดยไม่ต้องเดินไปจ่ายที่แคชเชียร์
- ในฐานะลูกค้าที่เป็นสมาชิก ฉันต้องการให้ยอดสั่งซื้อถูกนับเป็นแต้มสะสมโดยอัตโนมัติ
- ในฐานะบาริสต้า ฉันต้องการเห็นออเดอร์ใหม่ที่ลูกค้าสั่งจากโต๊ะ ปรากฏบนจอ KDS ทันทีที่มีการชำระเงินสำเร็จ

## Business Rules / เงื่อนไข

- 1 QR Code ผูกกับ 1 หมายเลขโต๊ะ ระบบต้องรู้ว่าออเดอร์มาจากโต๊ะไหน
- ออเดอร์จะถูกส่งไปแสดงบน KDS ก็ต่อเมื่อการชำระเงินสำเร็จแล้วเท่านั้น
- แต้มสะสมคำนวณจากยอดชำระที่สำเร็จเท่านั้น ในอัตรา **ทุกยอดชำระสำเร็จ 10 บาท = 1 แต้ม โดยปัดเศษลง (floor)** เช่น ยอดชำระ 185 บาท ÷ 10 = 18.5 → ได้รับ 18 แต้ม (ยืนยันกับ user แล้วเมื่อ 2026-08-29)
- ระบบต้องรองรับช่องทางชำระเงินออนไลน์อย่างน้อย 3 ช่องทาง: **พร้อมเพย์ (QR payment), บัตรเครดิต/เดบิต, และ e-wallet** (ยืนยันกับ user แล้วเมื่อ 2026-08-29)
- เมื่อชำระเงินไม่สำเร็จ ลูกค้าต้องสามารถลองชำระเงินใหม่ได้กับออเดอร์เดิม **สูงสุด 3 ครั้ง** ถ้าครบ 3 ครั้งแล้วยังไม่สำเร็จ ระบบต้องไม่ให้ลองชำระซ้ำในออเดอร์เดิมอีก และให้ลูกค้าเริ่มออเดอร์ใหม่แทน (ยืนยันกับ user แล้วเมื่อ 2026-08-29 — เป็นค่าที่แนะนำโดย AI เพื่อป้องกันลูกค้าติดลูปลองจ่ายไม่จำกัดครั้งบนหน้าจอที่โต๊ะ ขณะเดียวกันยังยืดหยุ่นพอสำหรับความล้มเหลวชั่วคราว เช่น เน็ตหลุด — ถ้าต้องการเปลี่ยนจำนวนครั้งภายหลังสามารถแจ้งเพื่อปรับได้)

## Acceptance Criteria

ร่างจาก User Stories และ Business Rules ด้านบน (ยืนยันเมื่อสร้าง test plan วันที่ 2026-08-29 และอัปเดตหลัง user ตอบ 3 ประเด็นที่เคยค้างในวันเดียวกัน)

- [ ] เมื่อลูกค้าสแกน QR Code ประจำโต๊ะ ระบบต้องเปิดหน้าเว็บสั่งเมนูพร้อมระบุหมายเลขโต๊ะที่ถูกต้องโดยอัตโนมัติ ตรงกับโต๊ะที่ QR Code นั้นผูกไว้ โดยไม่ต้องติดตั้งแอป
- [ ] ลูกค้าต้องสามารถเลือกเมนู ใส่ตะกร้า ปรับจำนวนสินค้า และดูยอดรวมได้ในหน้าเว็บเดียวกันก่อนยืนยันคำสั่งซื้อ
- [ ] ลูกค้าต้องสามารถชำระเงินผ่านระบบได้ทันทีหลังยืนยันคำสั่งซื้อ โดยไม่ต้องเดินไปชำระที่แคชเชียร์ ผ่านช่องทางที่รองรับอย่างน้อย 3 ช่องทาง: พร้อมเพย์ (QR payment), บัตรเครดิต/เดบิต, และ e-wallet
- [ ] เมื่อชำระเงินสำเร็จ ระบบต้องส่งออเดอร์ไปแสดงบนจอ KDS ทันที (อัปเดตแบบเรียลไทม์) พร้อมหมายเลขโต๊ะและรายการเมนูที่สั่ง
- [ ] เมื่อชำระเงินไม่สำเร็จ ระบบต้อง**ไม่**ส่งออเดอร์ไปแสดงบนจอ KDS และต้องแจ้งลูกค้าว่าชำระเงินไม่สำเร็จอย่างชัดเจน พร้อมเปิดให้ลองชำระเงินใหม่ได้กับออเดอร์เดิม
- [ ] ลูกค้าต้องลองชำระเงินใหม่กับออเดอร์เดิมได้สูงสุด 3 ครั้ง — ถ้าครบ 3 ครั้งแล้วยังไม่สำเร็จ ระบบต้องไม่ให้ลองชำระซ้ำในออเดอร์เดิมอีก และต้องแจ้งให้ลูกค้าเริ่มออเดอร์ใหม่แทน
- [ ] เมื่อชำระเงินสำเร็จและลูกค้าเป็นสมาชิก ระบบต้องคำนวณแต้มสะสมจากยอดชำระที่สำเร็จเท่านั้น ในอัตราทุก 10 บาท = 1 แต้ม โดยปัดเศษลง (floor) เช่น ยอดชำระ 185 บาท ต้องได้รับ 18 แต้ม (ไม่ใช่ 19) และแสดงจำนวนแต้มที่ได้รับให้ลูกค้าเห็นหลังชำระเงินสำเร็จ
- [ ] เมื่อชำระเงินไม่สำเร็จ ระบบต้องไม่คำนวณ/ไม่บันทึกแต้มสะสมใดๆ ให้สมาชิก
- [ ] ลูกค้าที่ไม่ใช่สมาชิก (สั่งแบบไม่เป็นสมาชิก) ต้องสามารถสั่งซื้อและชำระเงินได้สำเร็จ โดยไม่ถูกบังคับให้สมัครสมาชิกก่อน
- [ ] ถ้าลูกค้าเลือกสมัครสมาชิกระหว่างขั้นตอนสั่งซื้อ ระบบต้องให้กดยินยอม (consent) พร้อมอ่าน privacy notice ก่อนการสมัครสมาชิกจะสำเร็จเสมอ — ถ้าไม่กดยินยอม ระบบต้องไม่สร้างบัญชีสมาชิก (อ้างอิงร่วมกับ [[20260807-03-audit-log-pdpa-compliance|20260807-03-audit-log-pdpa-compliance]])
- [ ] ทุกออเดอร์ที่บาริสต้าเห็นบนจอ KDS ต้องเป็นออเดอร์ที่ชำระเงินสำเร็จแล้วเท่านั้น (ไม่มีออเดอร์ที่ยังไม่ชำระ/ชำระไม่สำเร็จปรากฏบนจอ)

## ประเด็นที่ยังไม่ชัดเจน (รอตัดสินใจในรอบถัดไป)

3 ประเด็นเดิม (ช่องทางชำระเงินที่รองรับ, อัตราการสะสมแต้ม, การจัดการกรณีชำระเงินไม่สำเร็จ) ได้รับการยืนยันกับ user แล้วเมื่อ 2026-08-29 (ดู Business Rules และ Acceptance Criteria ด้านบน) — หมายเหตุ: เงื่อนไข "ลองชำระใหม่ได้สูงสุด 3 ครั้ง" เป็นค่าที่ AI แนะนำแทน user ตามคำขอ "แนะนำให้เลย" ไม่ใช่ตัวเลขที่ user กำหนดเองโดยตรง หากต้องการปรับภายหลังสามารถแจ้งได้

ปัจจุบันไม่มีประเด็นค้างเพิ่มเติมในสเปคนี้ นอกจากประเด็นที่ระบุไว้แล้วในเอกสารออกแบบที่ต่อยอด (เช่น สถานะออเดอร์บน KDS หลังบาริสต้าเริ่มทำ ซึ่งเป็นเรื่องใหม่ที่ยังไม่มี requirement รองรับ — ดู [[../../02-design/01-prototypes/20260829-01-user-journeys|user journeys]] Journey 2)
